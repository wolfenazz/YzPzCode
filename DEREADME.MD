## ⚡ Warum YzPzCode?

KI-gestützte Entwicklung wird meist zu einem Wechselspiel zwischen Terminal-Tabs, Agenten, Browsern, IDEs und einzelnen CLIs. **YzPzCode ersetzt dieses Jonglieren mit Fenstern durch eine native Kommandozentrale.**

| Herkömmlicher Workflow | mit YzPzCode |
| :--- | :--- |
| 🪟 8+ voneinander getrennte Terminalfenster | 🖥️ **Ein nativer Workspace** mit eigenen Layouts |
| 🔄 Ständiger Kontextwechsel per `Alt+Tab` | 🎛️ **Nebeneinander angeordnetes Terminalraster** mit echten PTY-Sitzungen |
| 🔌 In externen IDEs eingeschlossene Assistenten- panels | 🧩 **Grafische Erweiterungen**, eingebettet in das Raster |
| ⚙️ Manuelle Build-Skripte und Ausführungsbefehle | ⚡ **Ausführen & Bauen** mit automatisch erkannten 15+ Ökosystemen |
| 🧩 Externer Editor und Dateibetrachter | 📝 **Eingebetteter Editor** mit virtualisiertem Dateibaum und Git |
| 🌐 Separater Browser für UI-Prüfungen | 🔍 **Integrierter Browser** mit visuellem Inspector, der Prompts an Agenten übergibt |
| 📱 Separates Emulatorfenster | 📲 **Fenster für Android- und iOS-Geräte** mit Flutter hot reload |
| 📄 Word, PowerPoint und ein separater KI-Chat | ✍️ **Writing- und Presentation-Studios** mit denselben KI-CLIs |
| 🔑 Wiederholte CLI-Installations- und Authentifizierungsprüfungen | 🔐 **Erkennung, Installation per Klick und Authentifizierungsstatus** |
| 🎨 Photoshop oder Figma für schnelle Bearbeitungen | 🖌️ **Ebenenbasierter Bildeditor** mit Mischmodi |

##  Grafische Workspace-Erweiterungen

Führe grafische Coding-Assistenten direkt neben deinen Shells und Agenten im Workspace-Raster aus. Drücke **`Ctrl+Shift+X`** oder klicke auf das Erweiterungssymbol in der Kopfzeile, um den Katalog zu öffnen.

| Erweiterung | Herausgeber | Beschreibung |
| :--- | :--- | :--- |
| **Google Antigravity** | Google | Googles offizieller agentischer Assistent mit Chat, Plänen und Codeänderungen. |
| **Kilo Code** | Kilo | mit dem visuellen Erweiterungspanel von Kilo programmieren, planen und debuggen. |
| **Cline** | Cline | Autonomer Coding-Assistent mit Plan-/Act-Modi und Freigabestufen für Tools. |
| **OpenAI Codex** | OpenAI | OpenAIs Coding-Erweiterung mit ChatGPT-Anmeldung und Codeunterstützung. |
| **Claude Code** | Anthropic | Visueller Coding-Assistent und Gesprächspanel von Anthropic. |
| **Continue** | Continue | Open-Source-Agent und Code-Chat mit Cloud- oder lokalen Modell-Backends. |
| **Amazon Q Developer** | AWS | Code-Chat und Inline-Feature-Entwicklung mit Amazon Q. |
| **Tabby** | TabbyML | Selbst gehosteter Coding-Assistent, verbunden mit einem privaten Tabby-Server. |
| **Windsurf Plugin** | Windsurf | Codeium-Assistent mit KI-Code-Chat und Codebase-Index. |
| **Mistral Vibe** | Mistral AI | Visueller Coding-Agent von Mistral mit Kontext, Gesprächen und Tools. |
| **Roo Code** | Roo Code | Agent aus der Cline-Familie mit benutzerdefinierten Modi, Multi-Modell-Unterstützung und Freigaben pro Schritt. |
| **Qoder CN** | Alibaba Cloud | Agentischer Coding-Assistent von Alibaba Cloud mit Chat- und Agentenmodi; Anmeldung erforderlich. |
| **Augment** | Augment Code | Coding-Agent mit einer für große Codebasen entwickelten Kontext-Engine; Anmeldung erforderlich. |
| **Nexrall Code** | Nexrall | Autonomer Coding-Agent mit Freigaben pro Schritt, Checkpoints und MCP-Tools; ein Konto ist erforderlich. |

- 🎛️ **Nebeneinander angeordnete Rasterlayouts**: Panels werden innerhalb des Terminalrasters mit Drag-and-drop-Neuordnung, interaktiver Größenänderung, Fokusvoreinstellungen und geteilten Layouts eingebunden.
- 📌 **Editor-Seitenleiste**: Ein Panel rechts am Editor andocken (`Ctrl+Alt+B`) und zwischen Raster und Dock verschieben, ohne es neu zu starten.
- 📨 **Prompt-Übergabe**: Eine Browser-Inspector-Auswahl oder UI-Referenz direkt an ein Assistentenpanel senden; der Prompt wird eingefügt und übermittelt, das Ergebnis erscheint in der Panel-Kopfzeile.
- 🌈 **Aktivitätsleuchten**: Panels erhalten denselben Arbeitsring und Abschlusseffekt wie Agententerminals.
- 📦 **Verwaltete Laufzeit ohne Konfiguration**: Eine verifizierte VSCodium-`reh-web`-Laufzeit wird mit festgelegten SHA-256-Digests und Open-VSX-Paketen bereitgestellt. Keine VS-Code- oder Node-Installation erforderlich.
- 🛡️ **Abgesicherte Sandbox**: Jeder Assistent läuft in einem isolierten untergeordneten Webview auf einer eigenen `panel-<uuid>.localhost:<port>`-Origin mit dauerhaftem Speicher und kann keine Tauri-Host-Befehle aufrufen.
- 🔒 **Workspace-Vertrauen und Persistenz**: Vertrauensfreigaben (`workspace-trust.json`) und der IndexedDB-Workbench-Status (`workbench-state.json`) werden pro Workspace gespeichert.

Siehe die [Dokumentation zu grafischen Workspace-Erweiterungen](docs/extensions.md) für Architektur, Laufzeitspezifikationen und Validierungsdetails.

##  Writing-, Präsentations- und Tabellen-Studios

<div align="center">
  <img src="docs/readme/studios.svg" width="100%" alt="Das Writing Studio mit Gliederung, seitenweisem Bericht und Assistent sowie das Presentation Studio mit Filmstreifen, Canvas und Designpanel" />
</div>

<br />

Neben dem Coding öffnet der Modus-Schalter der Setup-Seite drei Dokumentstudios. Sie benötigen weder Terminals noch IDEs, führen die KI über bereits installierte CLIs (Claude Code, Codex, Grok, Antigravity, OpenCode) in einem headless Runner aus und speichern alles in einem Ordner, `Documents/YzPzCode`, damit Berichte, Decks und Arbeitsmappen auch nach einer Neuinstallation wieder gefunden werden.

<table>
<tr>
<td width="50%" valign="top">

###  Writing Studio

- **30 Berichtsarten**: Eine Art auswählen und eine Frage in einem einzeiligen Composer beantworten; Dateien anhängen, Material einfügen, Referenzen hinzufügen
- **Seitenweiser Streaming-Editor**: Gliederung mit Live-Abschnittsstatus, Tabellen, Abbildungen, Zitaten und Fußnoten, wobei die Leseposition gehalten wird, während Abschnitte gestreamt werden
- **Assistent**: Verbleibende Abschnitte schreiben, Auswahl oder Abschnitt umformulieren, das gesamte Dokument humanisieren oder neu schreiben, mit einer Review-Karte für jede Änderung
- **Humanizer und Linter**: Natürlichkeitswert mit Prüfungen für Standardformulierungen, Einstiege, Rhythmus und Gedankenstriche, optional mit Hervorhebung
- **Designpanel**: sechs Vorlagen, Schriftarten, Farben mit Seiten- und Struktursteuerung und **mit KI neu gestalten** mit Rückgängigmachen per Klick
- **Echte Webfotos**: Offen lizenzierte Bilder von Openverse, Unsplash oder Pexels mit Quellenangabe, niemals KI-Bilder
- **Export**: PDF, Word `.docx`, eigenständiges HTML; vorhandene `.docx` importieren

</td>
<td width="50%" valign="top">

###  Presentation Studio

- **KI-entworfene Decks**: Deck beschreiben; die KI erfindet ein Designsystem, schreibt eine Storyline mit Briefings pro Seite und zeichnet anschließend jede Folie als SVG
- **Echter Folieneditor**: Auswählen, Auswahlrahmen, mit Hilfslinien ziehen, Größe ändern, direkt tippen, Formen, Bilder, Tabellen, Gruppen, Formatleiste
- **mit KI bearbeiten**: Eine Folie, mehrere Folien oder das gesamte Deck ändern; jede Änderung ist ein Vorschlag mit Behalten oder Verwerfen, Stapel werden nebeneinander geprüft
- **Animation**: Eingangs-, Hervorhebungs- und Ausgangseffekte, Klickreihenfolge, Absatzaufbau und KI-entworfene Bewegung
- **Bilder**: Dateien oder Ordner ablegen, Pfade im Prompt nennen oder echte Webfotos hinzufügen
- **PowerPoint-Roundtrip**: `.pptx` importieren, wie PowerPoint es zeichnet; editierbares PowerPoint, PowerPoint mit „exakter Darstellung“, PDF, PNG und HTML exportieren
- **Präsentationsmodus**: Vollbildshow, Referentenansicht mit Notizen, Timer und Tempo, Übergänge und Sprachausgabe

</td>
</tr>
</table>

###  Arabisch und von rechts nach links, erstklassig unterstützt

Arabisch, Hebräisch, Persisch und Urdu funktionieren in beiden Studios: Die Absatzrichtung folgt dem Text, gedruckte Bezeichnungen (Kapitel, Tabelle, Abbildung, Inhaltsverzeichnis …) folgen der Dokumentsprache, Word- und PowerPoint-Exporte schreiben echte bidirektionale Absätze und ein Katalog mit etwa 150 Schriftarten (Latein und Arabisch, mit gebündelten `@fontsource`-Schriften) versorgt jede Schriftauswahl.

##  Fenster für mobile Geräte

<div align="center">
  <img src="docs/readme/devices.svg" width="100%" alt="Ein Android-Emulator und ein iOS-Simulator werden neben einem Flutter-Projekt mit hot reload in den Workspace gestreamt" />
</div>

<br />

Ein Gerätefenster gleitet am rechten Rand jeder Workspace-Ansicht (Terminal, Erweiterungen, Editor, Browser) herein und schiebt die Ansicht zur Seite, statt darüber zu schweben, sodass native Webviews nie verdeckt werden.

- 🤖 **Eingebetteter Android-Emulator**: AVDs in der App erstellen und starten; der Bildschirm wird in das Fenster gestreamt (gRPC-Frames über das gemeinsame `frame-codec`-Crate) mit Touch, Multi-Touch, Tastatur, Scrollen, Drehung, Skins und Screenshots.
- 🍎 **iOS-Simulator (macOS)**: Erkennung und Lebenszyklus über `simctl`, Bildschirm und Eingaben über `idb_companion`. Außerhalb von macOS wird er als nicht verfügbar gemeldet.
- 🐦 **Flutter-Ausführungsleiste**: Die Workspace-App auf dem ausgewählten Gerät mit hot reload ausführen (auch beim Speichern von `.dart`), hot restart und Live-Log.
- 🛠️ **Geführte Einrichtung**: **Settings → Environment** prüft die Toolchain von Flutter, Android (und Xcode unter macOS) und bietet Ein-Klick-Korrekturen für fehlende SDK-Bestandteile und Hardwarebeschleunigung.

##  Lokale Sprachausgabe

<div align="center">
  <img src="docs/readme/narration.svg" width="100%" alt="Eine Wellenform und die drei lokalen Stimmen SILMA, Lahgtna-Chatterbox und Kokoro" />
</div>

<br />

Berichte und Folien können vorgelesen werden, ohne Text an einen Cloud-Dienst zu senden. Die Sprachausgabe läuft in einer verwalteten lokalen Python-Umgebung und lädt Modelle bei Bedarf herunter (**Settings → Narration**).

| Modell | Sprachen | Größe | Hinweise |
| :--- | :---: | :---: | :--- |
| **SILMA TTS v1** (Standard) | Arabisch + Englisch | ~2.5 GB | Ausgewogene zweisprachige Stimme, Tashkeel-aware |
| **Lahgtna-Chatterbox** | Arabisch | ~1.5 GB | Ägyptische, saudische, marokkanische und irakische Dialekte |
| **Kokoro-82M** | Englisch | ~350 MB | Sehr schnell, geeignet für lange Berichte |

Die Sprache wird aus dem Text erkannt, die Geschwindigkeit beträgt 0.75× / 1× / 1.25× und synthetisiertes Audio wird auf dem Datenträger zwischengespeichert (LRU, Begrenzung 500 MB). Im Writing Studio können Auswahl oder Abschnitt vorgelesen werden, ebenso Folien im Presentation Studio und im Präsentationsmodus.

##  System zum Ausführen und Bauen von Anwendungen

Anwendungen ohne Konfiguration starten, bauen und debuggen. Projektmanifeste und ausführbare Einstiegspunkte werden in 15+ Ökosystemen direkt in den Terminal-Kopfzeilen erkannt.

<div align="center">

| Ökosystem | Erkennung und Ausführung |
| :--- | :--- |
| **Python** | Erkennt `.py`-Skripte, `main.py`, `app.py`, Djangos `manage.py` sowie Flask- und FastAPI-Server. Bevorzugt lokales `.venv`, `venv` oder System-Python. |
| **JavaScript / TypeScript** | Findet Dev-, Start- und Build-Skripte in `package.json`. Ruft anhand der Lockdatei `npm`, `pnpm`, `Yarn` oder `Bun` auf. |
| **Rust / Go / Flutter** | Cargo (`cargo run`), Go-Module (`go run .`) und Flutter-Projektmanifeste (`flutter run`). |
| **C / C++** | Findet Quellen mit `main()`, kompiliert über GCC oder Clang nach `.yzpz-run/` und führt die Binärdatei aus. |
| **CMake** | Liest die CMake File API, um Debug-Ziele in `.yzpz-build/` zu finden, und baut vor dem Start. |
| **C# (.NET)** | Findet und startet ausführbare `.csproj`-Dateien in Projekten und Lösungen mit dem .NET SDK. |
| **Java** | Ausführung von Einzeldateiquellen über JDK 11+ und Startkonfigurationen von Projekten. |
| **Ruby, PHP, Dart, Swift, Lua, Perl, R** | Führt Einstiegspunkte mit installierten Interpretern aus; Manifestbefehle für Rails und Laravel. |

</div>

- ▶️ **Ausführen und Bauen per Klick** über die Terminal-Kopfzeile mit sofortigem Wechsel des Ziels.
- 💬 **Interaktive stdin-Konsole**: Eingaben an laufende Programme senden (`input()`, `scanf()`, `Console.ReadLine()`) über die Terminal-Eingabeleiste.
- 🌐 **Automatische Erkennung von Dev-Servern**: Localhost-URLs in der Terminalausgabe werden zu einer Vorschau per Klick in der Browserleiste.
- ⚙️ **Benutzerdefinierte Ausführungskonfigurationen**: Befehle, Umgebungsvariablen, Argumente und Arbeitsverzeichnisse unter **Settings → Application runs**, global oder pro Workspace.

Siehe den [Leitfaden zu Anwendungsausführungen](docs/application-runs.md) für Konfigurationsschemas, den Wechsel zwischen mehreren Zielen und Compilerdetails.

##  Kernfunktionen

<details open>
<summary><b> Multi-Agenten-Terminalraster</b></summary>

<br />

- **Echtes PTY-Backend**: xterm.js-6-Frontend, betrieben durch Rusts `portable-pty`
- **Verwaltete Befehle**: nicht interaktive und Hintergrundaufgaben mit PID, Exit-Code und Live-Output-Streaming
- **Terminal-Mausmodi**: vollständige xterm-Mausberichterstattung (Klick, Ziehen, beliebiges Ereignis, Application Tracking) für TUIs
- **Hardwarebeschleunigtes Rendering**: Canvas-/WebGL-Pipeline mit Dirty-Rectangle-Aktualisierungen für geringe Latenz
- **Workspace-Sichtbarkeit**: Sitzungen sind pro Projekt-Workspace isoliert
- **Startdialog**: durchsuchbar, gruppiert nach Shells, primären Agenten, zusätzlichen Agenten und SaaS-Tool-CLIs, mit Live-Status-Badges
- **Agentenaktivitätsanzeige**: idle → working → done pro Bereich, mit Arbeitsring, Abschlusseffekt und optionalem Abschlussklang
- **Dynamische Layouts**: Layouts passen sich der Anzahl der Bereiche an, mit Drag-and-drop-Neuordnung und Layoutauswahl
- **Editor-Terminalpanel**: VS-Code-artiges Terminal unter dem Editor (<kbd>Ctrl</kbd>+<kbd>`</kbd> schaltet um, <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>`</kbd> öffnet eine neue Shell) mit Shell-Auswahl und Scrollback pro Workspace
- **Kachelung externer Terminals**: native Konsolen (Windows Terminal, macOS Terminal, Linux) mit automatischer Kachelung

</details>

<details>
<summary><b> Editor, Vorschauen und Quellcodeverwaltung</b></summary>

<br />

- **Workspace mit mehreren Tabs**: geteilte Ansichten und Tab-Verwaltung (andere / rechte / gespeicherte schließen)
- **Syntaxhervorhebung und Minimap**: Monaco- und CodeMirror-Engines
- **Umfangreiche Vorschauen**: Markdown, PDF, CSV, Excel (`.xlsx`), Word (`.docx`) und Draw.io-Diagramme
- **Medien- und Binärvorschauen**: Audio (Wellenform, Transport, Geschwindigkeit, Schleife) und per HTTP-Range-Unterstützung gestreamtes Video sowie eine Hexansicht für andere Binärdateien

- **OS-Zwischenablage im Explorer**: Dateien (und Zwischenablagebilder) zwischen Explorer und Betriebssystem kopieren, ausschneiden und einfügen, mit Ergebnissen pro Element und Rückgängigmachen
- **Im Terminal öffnen**: jeden Ordner in einem neuen integrierten Bereich oder einem externen Terminal öffnen

</details>

<details>

- **Tiefer Element-Inspector**: berechnetes CSS, Pseudoelemente, Box-Modell und DOM-Hierarchie
- **Style-Picker und -Generator**: Styles erfassen, atomare CSS-Klassen erzeugen und mit vollständigem Rückgängig-Stapel anwenden
- **UI-Element-Erfassung**: Struktur, Layout, Typografie, Pseudoelemente, Assets und Designabsicht als wiederverwendbare UI-Referenzen
- **Tabs, Startseite und Gerätesimulation**: Tabs pro Workspace, eine Startseite mit Live-Dev-Servern, Gerätevoreinstellungen und benutzerdefinierten Viewports
- **Dev-Server-Integration**: Vorschau per Klick, sobald ein Dev-Server eine lokale URL ausgibt

</details>

##  Download und Installation

### Option 1: Vorab erstellte Binärdateien (empfohlen)

Den neuesten Installer von der **[Releases-Seite](https://github.com/wolfenazz/YzPzCode/releases/latest)** herunterladen:

| Plattform | Paketformat | Architektur |
| :--- | :--- | :--- |
| **🪟 Windows** | `.msi` / `.exe`-Installer | x86_64 |
| **🍎 macOS** | `.dmg`-Installer | Apple Silicon (`aarch64`) und Intel (`x86_64`) |
| **🐧 Linux** | `.deb` / `.AppImage` | x86_64 |

> [!TIP]
> **macOS**: Bei einem unsignierten Build mit **Rechtsklick → Öffnen** öffnen oder unter *System Settings → Privacy & Security → Open Anyway* zulassen.

### Option 2: Aus dem Quellcode bauen

**Voraussetzungen:** Node.js `22.x` oder höher, die aktuelle stabile Rust-Toolchain (`rustup update stable`) und C++-Buildtools (Visual Studio Build Tools unter Windows, Xcode CLI Tools unter macOS, `build-essential` unter Linux).

```bash
git clone https://github.com/wolfenazz/YzPzCode.git
cd YzPzCode/app

npm install            # Frontend-Abhängigkeiten
npm run tauri dev      # Entwicklungsmodus (Port 8745)
npm run tauri build    # Produktions-Installer
```

Die kompilierten Binärdateien werden unter `app/src-tauri/target/release/bundle/` abgelegt.

##  Sicherheit und Datenschutz

YzPzCode ist **local-first** aufgebaut:

- 🛡️ **Der Code bleibt lokal**: Projektdateien und Quellcode werden von YzPzCode selbst nie auf Server von Drittanbietern hochgeladen.
- 🔑 **Lokal gespeicherte Geheimnisse**: API-Schlüssel und Tokens verbleiben ausschließlich auf dem eigenen Rechner.
- 📡 **Direkte Verbindungen zu Anbietern**: Anfragen gehen direkt an die offiziellen Endpunkte der konfigurierten Anbieter.
- 🔊 **Sprachausgabe auf dem Gerät**: Text-to-Speech-Modelle laufen lokal; nichts wird an einen Sprachdienst gesendet.
