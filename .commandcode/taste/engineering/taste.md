# Engineering taste

- Wants the app fully self-contained and reliable on any fresh Mac/Windows/Linux machine, including auto-detecting and auto-installing missing prerequisites (e.g., Node.js 22+) instead of requiring manual setup. Confidence: 0.8
- Treats performance/stability as critical: any OS lag, high CPU, or crash (e.g., while running dev servers) must be root-caused and fixed; the app should be smooth and light. Confidence: 0.8
- Wants the in-app terminal to behave and look exactly like the system CMD/PowerShell: Cascadia Mono font, smooth scrolling, working mouse support, no text-overlap/glitch rendering. Confidence: 0.8
- Wants every child process the app spawns on Windows to be launched hidden (CREATE_NO_WINDOW / windowsHide) so no visible console/CMD window ever flashes during background work. Confidence: 0.8
- Prefers driving releases through GitHub CLI (gh): commit, bump version, tag (v*), push, and trigger/watch the GitHub Actions release workflow so updates deploy to users. Confidence: 0.8
- Adds explicit type annotations to callback handler parameters (e.g. `onAuth: (info: { url: string }) =>`) instead of relying on contextual typing flowing through SDK `exports` maps under NodeNext, which routinely fails to infer. Confidence: 0.9
- Never exposes provider secrets to the renderer; always projects configs into safe status-only shapes (`hasApiKey`/`hasOAuth` booleans + `oauthEmail: string | null`) and strips `apiKey`/`oauth` token objects from any settings view sent over the bridge. Confidence: 0.9
- Uses long custom `Duration` timeouts for OAuth/browser round-trip flows (e.g. 600s for login, ~120s for manual-code prompt resolution) rather than default/empty timeouts. Confidence: 0.85
- Typechecks before building: runs `tsc --noEmit` / `cargo check` first, filters `node_modules` out of error output, and writes logs to scratchpad/temp directories rather than relying on stdout. Confidence: 0.85
- Runs long-running verification (e.g. `cargo check`) in the background while continuing other work, surfacing only targeted finish/error lines. Confidence: 0.8
- For large/multi-area tasks, enters plan mode: researches the codebase with parallel explore sub-agents, asks the user structured scoping questions (with recommended options) to lock scope, writes a plan file, and gets sign-off before implementing phase-by-phase. Confidence: 0.8
- Makes surgical changes only to files relevant to the task — explicitly avoids formatting or reformatting the user's own uncommitted/in-progress files (e.g. rustfmt/cargo fmt only files the agent authored) and flags this in the summary. When the same root-cause bug affects other unreported components, fixes only the reported issue and surfaces the same-class defects (e.g. other fixed-position overlays demoted by the same theme rule) as a heads-up for the user to decide, rather than broadening scope unasked. Confidence: 0.8
- Verifies framework/library semantics against the official docs before applying a fix (e.g. confirming Tauri v2's `data-tauri-drag-region` applies only to the exact element, not children) rather than guessing from prior runtime knowledge, then bases the implementation on those documented semantics. Confidence: 0.8
- Prefers to fix a repeated cross-cutting defect once in a shared, reusable abstraction (e.g. a `useTitlebarDrag` hook) and wire it into every affected component/header rather than patching each occurrence individually. Confidence: 0.8
- When fixing non-functional CSS features (e.g. a dead UI Density setting whose `.density-*` rules targeted selectors no component uses), traces the wiring end-to-end (component → store → styles) to confirm dead code before rewiring it to actually take effect. Confidence: 0.8
- Verifies CSS/appearance changes by running the production build (e.g. `npx vite build`) and confirming the new rules appear in the compiled output, not just by editing source. Confidence: 0.8
- After any build, checks `git status --short` to ensure generated build artifacts (e.g. `dist/`) do not leak into the version-controlled working tree. Confidence: 0.75
- On this Windows machine, resolves dev-server "port already in use" errors with PowerShell: find the listener via `Get-NetTCPConnection -LocalPort <port> -State Listen`, identify the owning PID (`Get-Process`) before killing anything, re-verify the port is actually free, and leave the user a reusable one-liner (`... | ForEach-Object { Stop-Process -Id $_ -Force }`) for recurrence. Confidence: 0.7
