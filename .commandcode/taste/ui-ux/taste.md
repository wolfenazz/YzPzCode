# UI/UX taste

- Wants the AI chat experience modeled on Codex: clean and calm, hiding raw tool outputs from regular users, and showing code changes as readable diffs ([+] / [-]) instead of dumping raw JSON/technical noise. Confidence: 0.9
- Wants the whole app to follow a terminal-modern theme: dark backgrounds, monospace accents, subtle green highlights, command-line-inspired details. Confidence: 0.9
- Wants tool inputs/results shown in human-readable form (commands, file paths, friendly labels) with raw JSON hidden behind an optional "view raw" toggle. Confidence: 0.8
- Prefers professional icon sets (e.g., Lucide) over hand-drawn/inline SVG icons; dislikes emoji/"AI-designed" iconography in the UI. Confidence: 0.9
- Considers UI that looks "sloppy" unacceptable; wants interfaces to look professional/premium — consistent design language, polish, and premium-feeling components, not just functional. Confidence: 0.7
- Wants predictable navigation: opening a file from the explorer should land in the normal/standard view, with an explicit top button to open a specialized editor (e.g., image editor) rather than auto-switching the user into it. Confidence: 0.6
- Wants key controls/buttons (e.g., header action buttons like New File/Folder, Refresh, Collapse All) always visible rather than hidden behind hover-reveal interactions — hover-only controls make users distractingly hunt for them. Confidence: 0.7
- Wants continuous visible activity feedback while the agent is working (loading/thinking/typing animations between every step) so the app never appears stuck. Confidence: 0.8
- Wants Arabic/RTL text rendered cleanly (no chunky or broken Arabic glyphs). Confidence: 0.7
- Wants editor/UI colors muted: dark mode slightly black, light mode grey — not bright white; the dark/light difference should be subtle. Confidence: 0.7
- Wants browser previews inside accurate device frames (iPhone/iPad) with the web content rendered underneath the frame's notch/dynamic island; keep only responsive + iPhone 14 Pro presets in the resolution picker. Confidence: 0.7
- Wants buttons to prefer icons over text labels, and key actions to be visually distinctive/premium (e.g., animated rainbow gradient border on the inspect button). Confidence: 0.7
- Wants minimal UI copy — titles only, no filler/instructional sentences. Confidence: 0.6
- Wants an in-app guided tour/explanation mode (highlighted steps with a next/back stepper) for first-time users. Confidence: 0.6
- Wants the browser to keep its page state when the user switches to other screens and back (no refresh on navigation). Confidence: 0.6
- Wants component surface colors (e.g., terminal/editor backgrounds) derived from the app's theme background variable as a slightly darker variant, so they update reactively when the background/light theme changes rather than being hardcoded colors that stay fixed across theme switches. Confidence: 0.7
- Wants generated designs saved under a "Design" folder with one subfolder per page. Confidence: 0.5
- Wants the chat to support sending images/files to the AI model when it accepts them. Confidence: 0.5
- Wants all background/automatic operations (e.g., fetching new models from providers) to be completely invisible to the user — no CMD/console windows or technical processes popping up; things should just happen automatically and hidden ("User does not need to see anything"). Confidence: 0.9
- Wants agent failures and silent turns surfaced with plain-language explanations plus a clear one-click recovery action (e.g., "Continue"), with the raw technical error still visible in smaller text rather than an opaque dead-end. Confidence: 0.55
- Redesign direction is a premium, minimal, high-end product UI modeled on Codex/Cursor: quiet warm-neutral surfaces, restrained contrast, crisp typography, and generous padding/margin — explicitly moving away from the "terminal looks" and geeky patterns. Confidence: 0.9
- Wants "AI slop" decoration removed: no decorative gradients, rainbow/multi-color flourishes, glowing borders, aurora backgrounds, shimmer/gradient text, or colorful composer elements. Confidence: 0.9
- Avoids all-caps microcopy, wide letter-spacing on nav/labels, and heavy "chunky" bold fonts; prefers normal-case labels, lighter weights, and a crisp typeface (e.g., Inter Variable). Confidence: 0.85
- Restricts monospace to terminal/code/diff/file-path content only — never for UI labels or metadata; keeps a system font (Inter) for the rest. Confidence: 0.8
- Typography should use light-to-medium weights (roughly 400–560), tight optical letter-spacing, antialiasing, and subtle weight hierarchy — dislikes chunky/condensed terminal fonts in the product UI. Confidence: 0.8
- Wants a single consistent icon family (e.g., Phosphor) app-wide and a single global font stack rather than hand-drawn inline SVGs or mixed typefaces. Confidence: 0.75
- Wants significant redesign work to set up a documented, reusable design system (shared tokens/primitives in a global CSS file, plus a written handoff/source-of-truth doc) so a cheaper/follow-up model can continue the migration coherently without drifting back; subsequent sessions are driven by re-reading the handoff doc and executing its remaining-pass list rather than re-planning; after each work session, the handoff doc must itself be re-updated to reflect exactly what was completed and what still remains unmodified (the user asks for this explicitly). Confidence: 0.9
- When a region is repurposed for a new interaction (e.g., making the titlebar a window drag region), interactive controls inside it (buttons, inputs, tabs, links) must keep working normally — only inert/empty space should trigger the new behavior. Confidence: 0.8
- Prefers conventional, system-standards-aligned feature designs over bespoke workarounds: e.g., replacing a one-off "Dark Text (Bright Background)" toggle with a standard Light/Dark/System theme selector that follows the OS theme, and exposing the switcher as an always-visible header control. Confidence: 0.6
- Prefers a lean settings surface: settings sections/features that aren't needed should be removed entirely (the UI section plus its underlying state/wiring), not kept around "just in case" ("It does not need it."). Confidence: 0.55
- When refining/enhancing any existing UI element (e.g., buttons, headers, badges), wants it to merge with and reuse the app's current design system and tokens — matching the anatomy/state patterns of adjacent sibling controls — rather than introducing a new or contrasting look that ignores the theme ("make it merge with the actual current design"). Confidence: 0.8
